# Stream budgets — 2026-10-11

Target: Densha de Go!! AC, TG4AC 5.80.02. IDA instance `ida-35608`.
Image base `0x140000000`. Runtime addresses are `TG4AC-Win64-Shipping.exe` base + RVA.

`features::Stream_Install` reads `[Stream] Enabled` from `moduleDir\config.ini`.
`Enabled=0` returns before any hook. A missing key defaults to on.

The cabinet slices load and release work so one frame stays short. These are the
knobs that exist in this exe. `MaxNumTexturesToStreamPerFrame` is not in the
binary. `gc.TimeBetweenPurgingPendingKillObjects` is present (image default
`60`, `DefaultEngine.ini` sets `300`) and is left alone: it is the wait between
purges, not a per-frame cap, and garbage collection stays enabled. Pool size,
`dgo.Streaming.PoolSizeKHTr`, mip-drop cvars, `sg.*`, and mesh LOD are left
alone. `r.VSyncDWM` is written by the same cabinet helpers; since 2026-10-12 it is forced to 0 (see `2026-10-12-touch-vsync-route.md`).
Which levels load is not changed.

## Cabinet writers

`dgo.OverwriteConsoleVariablesInLoadingScreen` (default `1`, cvar object
`qword_142DD15D0`, value pointer `qword_142DD15D8`) gates the load-screen
writer. Its help text says a non-zero value sets console variables to optimize
loading time.

| Role | VA | RVA |
| --- | --- | --- |
| Set while the load screen is up | `sub_140204A50` | `0x204A50` |
| Restore after that | `sub_140203080` | `0x203080` |

Both resolve the cvar through the console manager (`qword_142DD7F50`, vtable
`off_14241A410`, find at `+136`) and call `IConsoleVariable::Set` at vtable
`+88` with `ECVF_SetByCode` (`0x08000000`).

| Cvar | Load screen | Restore |
| --- | --- | --- |
| `s.AsyncLoadingTimeLimit` | `100` | `5` |
| `s.LevelStreamingActorsUpdateTimeLimit` | `300` | `5` |
| `r.VSyncDWM` | `0` | `1` |

`sub_140301B30` and `sub_1402FEE20` are the exec thunks that call those two.

## Hook

Ini load and the cabinet both go through `Set`. The hook replaces a tighter
incoming value and calls the original `Set`, so a later cabinet write does not
stick. Ref cvars are also stored in `.data`; those globals are written at
install because that is what the slice checks read. Owned cvars keep the int
inside the object (`GetData` is `sub_14138A280`, returns `this+104`). Their
registration functions are hooked so the constructor default is replaced
before a frame, and the same apply runs immediately if the cvar already exists.

| Set | VA | RVA | Objects |
| --- | --- | --- | --- |
| Float ref | `sub_140472480` | `0x472480` | vtable `off_14241A870`, value pointer at `+104` |
| Int ref | `sub_1404723F0` | `0x4723F0` | vtable `off_14241ABB0`, value pointer at `+104` |
| Owned int | `sub_140472200` | `0x472200` | vtable `off_14241A6F0`, value at `+104` |

Registration hooks: `sub_14014E150` (`0x14E150`) for
`r.Streaming.FramesForFullUpdate`, `sub_14014E850` (`0x14E850`) for
`r.Streaming.NumStaticComponentsProcessedPerFrame`.

## Knobs

Image defaults below are the `.data` initializers or the `RegisterConsoleVariable`
immediate. `BaseEngine.ini` repeats the same `5`, `20`, `10`, `5`, and `1`
under `[/Script/Engine.StreamingSettings]`.

| Cvar | Original | Forced | Why this value |
| --- | --- | --- | --- |
| `s.AsyncLoadingTimeLimit` | `5` ms | `10000` ms | `sub_1412B4510` loads this float and scales it by `0.001`. The cabinet writes `5` or `100`. |
| `s.PriorityAsyncLoadingExtraTime` | `20` ms | `10000` ms | Extra time on a high-priority load. Same float-ref `Set`. |
| `s.LevelStreamingActorsUpdateTimeLimit` | `5` ms | `10000` ms | `sub_1416171C0` and `sub_14160F550` stop when elapsed ms is greater than this. `0` stops on the first check. The cabinet writes `5` or `300`. |
| `s.UnregisterComponentsTimeLimit` | `1` ms | `0` | `sub_14161AE50` timeslices only when this is `> 0`. `0` takes the full unregister path. Help text matches. |
| `s.AsyncLoadingUseFullTimeLimit` | `1` | `1` | `sub_1412B4510` passes this as the "use the whole limit" flag. A later `0` is written back to `1`. |
| `s.LevelStreamingComponentsRegistrationGranularity` | `10` | `0` | `sub_1410A8750` turns `0` into `0x7FFFFFFF`. `sub_141345B40` then walks every component. |
| `s.LevelStreamingComponentsUnregistrationGranularity` | `5` | `2147483647` | `sub_141345A80` stops once the running count exceeds the argument. `0` is a one-step cap. Unused while the unregister time limit is `0`. |
| `r.Streaming.FramesForFullUpdate` | `5` | `0` | `sub_1415A7560` takes the full texture update when this is not `> 0`. |
| `r.Streaming.NumStaticComponentsProcessedPerFrame` | `50` | `0` | `sub_14159F4F0` treats `<= 0` as no cap (`0x7FFFFFFFFFFFFFFF`). |

Each line is logged once as `Stream <name> <original> -> <forced>`. The first
later `Set` that is tighter is logged once as `later set <incoming> kept <forced>`.
