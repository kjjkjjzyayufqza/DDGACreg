# Game keys — 2026-10-11

The shipping game does not list its keyboard cheat map in `DefaultInput.ini`.
That file only sets the console key and the engine fullscreen toggles.
`Config/DefaultGame.ini` turns the keyboard path on:

- `UseKeyboardDevice=True`
- `EnableCheatKey=True`
- `SplitScreens=4`
- `ConsoleKeys=Tidle` (the engine console key, Tilde)
- `bF11TogglesFullscreen=True`
- `bAltEnterTogglesFullscreen=True`

The bindings themselves are Unreal input-key nodes in
`Content/Blueprints/gamemodes/KeyEmulator/`. `KeyEmurateType` selects which
child runs: `OutGame`, `InGame`, `TestMode`, or `AuthInGame`. The in-game,
out-game, and test-mode graphs all read `EnableCheatKey` before the cheat
keys do anything. Test mode's level is `/Game/Maps/TestMode/TestModeLevel`.

Node names below are the `InpActEvt_<Key>_K2Node_InputKeyEvent` exports.
They are the keys the blueprint actually listens for. The cooked ubergraph
stores each key's entry as a bytecode offset in the pre-strip address space
(`ScriptBytecodeSize` 22095, stored script 13835). Offsets at the very end
line up with the jump table. Offsets earlier in the script land a few bytes
off a statement, so nearest-statement snapping swaps neighbors. Actions below
are decoded from calls that parse cleanly. A key is named on an action only
where that link is exact or was checked in play.

## Cabinet keys (KeyEmulatorBase)

These are the keyboard stand-in for the cabinet, on every mode:

`Up`, `Down`, `Enter`, `SpaceBar`, `[`, `]`, `\`, `/`, `RightShift`,
`Shift+C`, thumb mouse button, mouse wheel.

Calls in that same graph: `MasterControllerAtKeyboard`,
`CoinSwitchAtKeyboard`, `EnterSwitchAtKeyboard`, `SelectSwitchAtKeyboard`,
`ServiceSwitchAtKeyboard`, `TestSwitchAtKeyboard`, `HornButtonAtKeyboard`,
`Horn2ButtonAtKeyboard`, `RightgripSwitchAtKeyboard`.

`Up` / `Down` are the master-controller axis. Do not bind them in the DLL.
Arrow left/right are not in this list.

## In-game cheat keys (InGameKeyEmulator)

Extra keys while `EnableCheatKey` is on, during a run:

`A` `B` `C` `D` `G` `H` `J` `L` `P` `Q` `R` `S` `W`,
numpad `+` `-` `*` `/` `.` `0`, `Colon`, `PageUp`, `PageDown`,
`LeftControl`, `RightControl`.

`G` skips ahead to the next station. The matching call is
`SetDistance(GetTrainDistance() + GetRemainDistance(), false)`: add the
distance already run to the distance still left, which is the end of the
current section.

Keys with a separate press and release event: `B`, numpad `+` `-` `*`,
`PageUp`, `PageDown`, `LeftControl`, `RightControl`. The graph implements
hold-style speed changes as `Array_Add` on press and `Array_RemoveItem` on
release, then `TrainSpeedUp`. `TrainSpeedUp` calls `StartHighSpeedFixed`
with `1000`, `-1000`, `100`, or `-100`, and can call `SetBackRun`.

Press-only keys: `A` `C` `D` `G` `H` `J` `L` `P` `Q` `R` `S` `W`, numpad
`/` `.` `0`, and `Colon`.

Other calls in the same ubergraph, each a one-shot cheat:

| Call | What it does |
| --- | --- |
| `SetDistance(0, false)` | Back to the start of the current section |
| `SetDistance(remain, false)` | Writes the remaining-distance value into `SetDistance` |
| `StartFixedKph(1)` / `StartFixedKph(-1)` | Lock a signed fixed speed |
| `StopFixedKph()` | Leave that lock |
| `FinishFixedKph(0)` | Finish the fixed-speed mode at 0 |
| `NextCameraType()` / `PrintCurrentCameraType()` | Step the debug camera, or print which one is active |
| `SetPlayerFreeze` / `IsPlayerFreeze` | Freeze or unfreeze the player |
| `SwitchBackRun` | Toggle reverse running |
| `ToggleAutorun` | Toggle auto-run |
| `Debug_HeadLightSettings(true/false, ...)` | Force the headlight on or off |
| `Debug_ForcedWiperActive` | Force the wiper |
| `PassengerSetting(0)` or `PassengerSetting(random 1..100)` | Stop-sway amount. Stores `clamp(n * 0.01, 0, 0.5)` on `SlopeControlComponent.Passenger`. `StopState` copies that into the stopped car's cycle area. 50 and above all become 0.5. This is separate from the route's station-interval `Passenger`, which drives TIMS load percent and crowd audio |
| `ChangePlayableScene(0)` | End the current scene component and mount `PlayableScene_Playing`. If the in-game sequence is not already Playable, force it there. The function can also mount `PlayableScene_Finish` when passed 1; both cheat call sites pass 0 |
| `OpenNewPersistentLevel('OutGame')` | Leave the run for the out-game level |
| `ExecuteConsoleCommand('SkipLaunchProduction')` | Skip the launch movie |
| `ExecuteConsoleCommand('FocusSplitPlayer -1')` | Console focus on a split player |
| `CheckReflectionCapture` | Debug the reflection capture |
| `ClearAllBits` / `MarkBit` / `GetUnmarkedBit` / `HasUnmarkedBit` | Unreal MultiGate bookkeeping for a 3-output gate. The outputs broadcast `AllHudVisiblityDelegate` with `HudVisibleType`: 1 AllHidden, 2 HUDsOnly, 0 AllVisibility, then repeat |
| `EnableChange` | Enable a debug change flag |

`Colon` is bound too. It is not in the key list from play.

## Test mode (TestModeKeyEmulator)

Additional keys: `F1`, `LeftShift`, `LeftControl`.

The graph opens a sub-mode (`OpenSubMode`, `OpenNewPersistentLevel`) and
tracks `FestivalModeSecretKeyState`. `F1` is the test-mode key in this
emulator. Do not bind `F1`.

Out-game only adds numpad `+`, `-`, and `*` (`OutGameKeyEmulator`), still
behind `EnableCheatKey`.

## Keys this DLL uses

| Key | Owner | Game also uses it? |
| --- | --- | --- |
| F2 | Free camera toggle | No |
| F3 | Coin | No |
| F11 | Borderless / windowed | Yes, engine fullscreen toggle |
| Ctrl+0..4 | Layout | Ctrl itself is `LeftControl` / `RightControl` |
| WASD, Space, C, Shift, Ctrl | Free camera, only while it is on | Yes |

While the free camera is on it keeps the pose it captured at toggle and
drops `WM_KEY*` for the keys it is driving, so those cheat bindings do not
run at the same time. `F1`, `G`, `Enter`, `Up`, `Down`, and the bracket
keys are not bound by the DLL. `Alt+F4` is not a layout key.
