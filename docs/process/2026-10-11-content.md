# Content server and host redirect — 2026-10-11

> Updated on 2026-10-12: the host hook on `sub_140228CF0` was removed. The first
> NESYS connection sets the hosts through another path, so pings still went to
> `game.ahac.nesica.net`. The NESYS service now sends every request under
> `/ahac-api/tg4gs/gs` to the content server. See `2026-10-12-nesys.md`.

Target stays TG4AC 5.80.02, IDA instance `ida-35608`, image base `0x140000000`.
Nothing in this session contacted an official host. The server binds
`127.0.0.1` only. SQLite is the public-domain amalgamation 3.54.0 under
`server/third_party/sqlite` (zip SHA3-256
`7b670a62fdfbd672b75fef004cb703c8a3e87d3a5cc7d675b4a08337004a2d93`).

## Host object

`sub_140228CF0` (`0x140228CF0`, RVA `0x228CF0`) stores two wide strings on its
`a1` object. Each string is `wchar_t*`, then a count that includes the NUL,
then a capacity.

| Offset | Role |
| --- | --- |
| `+184` | Resolved address. Planted as `0.0.0.0`, then replaced if a resolver returns one. |
| `+296` | Profile token (`game`, `stg`, `stg2`, `stg3`, `dev`, `dev2`, `stgtiny`). |
| `+312` | Game host, no scheme. Example: `game.ahac.nesica.net/ahac-api/tg4gs/gs`. |
| `+328` | Photo host. Example: `game.photo.ahac.nesica.net/ahac-api/tg4gs/gs`. |

`stgtiny` is the exception in the profile table: its game host is
`stg.tiny.nesica.net/ahac-api/tg4gs/gs` (count 38, including NUL) and its photo
host is `stg.photo.tiny.nesica.net/ahac-api/tg4gs/gs` (count 44). The other
profiles use `<profile>.ahac.nesica.net` and `<profile>.photo.ahac.nesica.net`.
The smallest game-host count is 38 (`stg`, `dev`, `stgtiny`). The rewritten
host `127.0.0.1:8750/ahac-api/tg4gs/gs` is 33 wchars including NUL, so it fits
in that buffer. `sub_140228CF0` returns `double`. Its resolver asks for the
profile token at `+296` (for example `game`), not the AHAC hostname.

The DLL hooks this function and, after it returns, writes
`127.0.0.1:<port>/ahac-api/tg4gs/gs` into both `+312` and `+328`. `<port>`
comes from `[Content] BaseUrl` (default `8750`). A non-loopback host in that
URL is not copied; the stored host is always `127.0.0.1`. When the existing
buffer is large enough the bytes are overwritten in place. Otherwise the
game allocator `sub_1413704D0` (`RVA 0x13704D0`) grows it, and
`sub_140489F70` (`RVA 0x489F70`) frees the previous buffer.

`sub_14023F520` is the HTTP POST builder used for `ping`. It concatenates:

`http://` + wide string at object `+312` + `/` + command

So a rewritten login URL is `http://127.0.0.1:8750/ahac-api/tg4gs/gs/login`.
The same shape is what the command-name stubs are for: each stub only widens
an ASCII command (`sub_140198080`) into a wide string the URL builder appends.

at `0x142399E38`. Success responses from this server omit `error`.

## Request documents

Setters: `sub_14055BD20` writes a number, `sub_14055BBF0` writes a bool,
`sub_14055C010` writes a string. `sub_140219C50` replaces the document with an
empty object. `sub_140219EF0` writes `player_id` from virtual `+648`.

`login` (`sub_14021A510`, vtable slot `0x1423D1A40`):

```json
{"player_id": 0, "relogin": false, "consume_ticket": 0, "change_customize": false}
```

`relogin`, `consume_ticket`, and `change_customize` are taken from the HTTP
object at `+104`, `+108`, and `+112`.

`addcredit` (`sub_14021A250`, vtable slot `0x1423D1F58`). The decompiler dropped
the numeric argument; the listing shows `movd xmm2, dword ptr [rbx+68h]` and
`[rbx+6Ch]` before `sub_14055BD20`:

```json
{"player_id": 1, "credit_num": 1, "service_credit_num": 0, "is_continue": false}
```

The server treats `credit_num` and `service_credit_num` as deltas and returns
the stored totals under those same names.

`gamestart` (`sub_14021E740`, vtable slot `0x1423A2E80`):

```json
{
  "player_id": 1,
  "game_mode": 1,
  "mission_mode": 0,
  "mission_type": 1,
  "mission_id": 0,
  "difficulty": 1,
  "timezone": 1,
  "isContinue": false,
  "badge": [{"id": 0, "position": 0}],
  "mission_ticket_id": 0
}
```

`game_mode`, `mission_type`, `difficulty`, and `timezone` are sent as
`(internal + 1)`. `badge` is built by `sub_140243A70`. The server records a
new `playlog_id` and, when `credit > 0`, spends one credit. That spend is a
local assumption; the request itself does not carry a credit delta.

`getmissionranking` (`sub_14021A870`, vtable slot `0x14239F5B8`) resets the
document and sends only:

```json
{"mission_id": 0, "difficulty": 0, "offset": 0, "count": 10}
```

`getstoremileageranking` (`sub_14021C900`, vtable slot `0x1423D2990`) resets
the document and sends `count` as the constant `20.0`.

`init` response parser is `sub_140211500` (vtable `0x1423A21A8`), next to the
`init` name slot at `0x1423A21D8`. It reads:

- `game_version` string
- `web_point_limit` number
- `rank_border` object, keys `D`, `C`, `B`, `A`, `S`, `SS` (`sub_140230960`)
- `discount_credit` array, optional. Item fields from `sub_14022BA00`:
  `comment` string, `type` number, `mission_category_credit` object,
  `mission_credit` object
- `disable_encounter_train` array, optional. Item fields from `sub_14022B560`:
  `train_line_id` number, `route_ids` array of numbers

Missing optional arrays are skipped. The server sends `game_version`,
`web_point_limit`, and `rank_border` only.

## Ranking response

`sub_140211C80` reads `start_at`, `end_at`, and `update_at` with the string
getter `sub_14055C730`, then `wtoi64`. They are decimal unix milliseconds, not
JSON numbers. `ranking` is an array (`sub_14055C0F0`). Each element is parsed
by `sub_140235210`:

| Field | Getter | Adjustment before it is stored |
| --- | --- | --- |
| `rank` | number | stored as json + 1 |
| `player_id` | number | as-is |
| `name` | string | required |
| `title_name` | string | required |
| `title_type` | number | stored as max(json - 1, 0) |
| `title_category` | number | stored as max(json, 0) |
| `title_rarity` | number | stored as max(json - 1, 0) |
| `title_train_line` | number | stored as max(json - 1, 0) |
| `title_ruby` | string | optional |
| `title_year` | number | required, as-is |
| `mode` | number | stored as `(byte)(json - 1)`; 0 becomes 255 |
| `value` | number | required, as-is |
| `store_name` | string | optional |

The seeded row is 1-based rank 1 in SQLite. The server emits `rank: 0` so the
game stores 1, and emits `mode` / `title_type` / `title_rarity` /
`title_train_line` as the stored byte plus one.

## Card and player

These UE class names were not ASCII command strings: `Http_SelectCard`,
`Http_RegisterCard`, `Http_ReissueCard`, `Http_CardUnlock`, `Http_PlayerConfig`,
`Http_PlayerBadge`, `Http_PlayerWappen`, `Http_InsertCredit`, `Http_GameOver`,
`Http_Result`, `Http_TotalResult`.

The cabinet card calls are native, not those stubs:

- `NESYS_CARD_SELECT(raw, 4, ansi param)` in `sub_14023EA30`, log string `0x1423A3FE0`
- `NESYS_CARD_INSERT(raw, 1, 1, jsonStr, jsonStr.Len(), 0)` in `sub_14023DA70`, log string `0x1423A4080`
- `NESYS_CARD_UPDATE(...)` in `sub_14023F0F0`

`sub_140213E60` is the player-information response parser used once a card
resolves:

- `exist` bool (`sub_14055B990`). When false, the rest is skipped.
- `player_id` number (`sub_14055B9F0`)
- `player_name` string (`sub_14055BAB0`)
- `tims` array (`sub_140235EC0`). Items may contain `id`, `train_id`,
  `custom_id` (numbers) and `name`, `description` (strings). An empty array
  is accepted.
- `title` object (`sub_140236740`). When present, the parser wants `id`,
  `type` (stored as json - 1), `category`, `rank` (stored as json - 1),
  `train_line` (stored as json - 1), `name`, `ruby`, `description`, `year`.

`playerbadge` and `playerwappen` are real command stubs (see below). The
remaining aliases `selectcard`, `registercard`, `reissuecard`, `cardunlock`,
`playerconfig`, and `playerdata` still answer with the player object. Those
spellings were not recovered as path bytes. The card id is not a recovered
JSON key. `NESYS_CARD_SELECT` passes one ANSI string. The server reads that
string from `card`, `card_code`, `cardid`, `card_id`, `raw`, `access_code`,
or `nesica_id`. `registercard` inserts a card and a new player when the code
is new. `selectcard` with an unknown code returns `{"exist":false}`. An empty
card code uses the seeded card `0123456789ABCDEF` / player `1` / name
`Local Player`.

`playerconfig` stores the raw JSON body in `player_data.config_json` and
echoes it back as `config`. That alias is not the `config` command. The
`config` stub is the sound-volume document below.

## Ping and bytes not recovered

`sub_14023F520` posts `ping` with header

`Content-type: application/x-www-form-urlencoded` + `\nContent-length: ` + `1`

and a one-byte post buffer that is `0`. The response body for `ping` was not
recovered. The server returns `{"result":1}`.

Also not recovered:

- The generic command POST header. Only `ping` showed `application/x-www-form-urlencoded`.
  `NESYS_CARD_INSERT` names its buffer `jsonStr`, so command bodies are treated as JSON.
  The server accepts either JSON or `application/x-www-form-urlencoded`.
- `ranking_reward` field list inside `sub_140230CB0` (size `0x8D9`). The
  response adds an empty `ranking_reward` array next to the shared ranking object.
- `sub_1402137B0` (size `0x6A8`) is on the store-ranking vtable at `0x1423D2970`
  and was not fully decompiled. Store ranking still uses the shared
  `start_at` / `end_at` / `update_at` / `ranking` shape.
- Shift-JIS text at `0x142399E38` (29 bytes) is only the failure `error` string.

## Shop, equip, and the player payload

Command stubs in `0x140221E20`–`0x1402232A0`. Wide-string stubs copy a
`wchar_t` literal (size `0x3e`). ASCII stubs call `sub_140198080`. Two HTTP
units use `sub_141388D80`, which returns an empty command, so the POST path
is `.../gs` or `.../gs/`. Every one of these posts through the host at object
`+312`, which the DLL already rewrites to `127.0.0.1`. No extra hook was added.

| Command | Stub | Request builder | Response parser |
| --- | --- | --- | --- |
| (empty) | `sub_141388D80` | `sub_140219C50` `{}` | `sub_140213E60` and `sub_140214460` |
| `iteminitialize` | `sub_140221F00` | `sub_14021A490` | `sub_1402116F0` |
| `config` | `sub_140222210` | `sub_14021BE10` | `sub_140212C30` |
| `playerbadge` | `sub_1402221D0` | `sub_14021BD70` | `sub_140212BE0` |
| `playerwappen` | `sub_140222260` | `sub_14021C120` | `sub_140212F20` |
| `purchasepoint` | `sub_1402230D0` | `sub_14021C160` | `sub_140213550` |
| `purchaseshopitem` | `sub_140223120` | `sub_14021C1E0` | `sub_140213690` |
| `shopinitialize` | `sub_140223200` | `sub_14021E730` (empty object) | `sub_140214C70` → `sub_140233350` |

Other stubs exist and are not implemented, because their parsers were not
field-complete: `playend`, `mission`, `gamemissionresult`, `getpicture`,
`getpicturelist`, `postpicture`, `discontinuation`, `gametotalresult`.
`ranking_reward` inside `sub_140230CB0` and the store-ranking parser
`sub_1402137B0` are still the shared ranking object. The server does not
invent fields for those.

`shopinitialize` response is an object with keys `badge`, `wappen`, and
`mission_ticket`. Each value is a map. The key is a decimal lineup id
(`wtoi`). The nested object requires `id`, `price`, `status` (byte), and
`buyable` (bool). The category byte is derived from the key: badge `9`,
wappen `11`, mission_ticket `12`.

`purchaseshopitem` request: `player_id`, `lineup_id` (int at `+104`), `num`
(int at `+108`). It does not send a price. The response parser stores
`meister_point` and replaces `badge_list`, `wappen_list`, and
`mission_ticket` when those arrays are present. Each element is `{id, num}`.
The server spends `price * num` web points, leaves `meister_point` unchanged,
and always sends all three arrays.

`purchasepoint` request: `player_id` plus `web_point` (the delta, int at
`+104`). Response: `web_point` and `total_web_point`. A positive delta is
added to both. Cabinet credit is not touched.

`iteminitialize` request: `item_category` = byte at `+104` plus 1. Response
arrays, each optional when the key is missing: `mission_ticket` (strict:
`id`, `mission_number`, `item_duration`, `max_num`, `name`, `description`,
`is_limit`, and `start_at` / `end_at` when `is_limit` is true), `wappen`
(`id`, `cell_type`, `max_num`, `name`, `description`), `wappen_set` (`id`,
`cell_type`, `name`, `description`, `wappen_ids`, `required_have_wappen_num`).
The seed sends one wappen catalog row and empty `mission_ticket` /
`wappen_set` arrays.

`playerbadge` request: `player_id`, `badge` array of `{id, position}`, and
`wappen_reset` bool. Response: `badge` (`id`, `position`) and `wappen`
(`id`, `size_type`, `position_x`, `position_y`). A missing `badge` key does
not clear equipped badges. `wappen_reset` true deletes equipped wappen.

`playerwappen` request: `player_id` and `wappen` array. Each element is
`id`, `position_x`, `position_y`, `size_type`. Response is the same `wappen`
array. Ids of 0 are not stored.

`config` request: `player_id` and `sound_config` with floats `bgm_volume`,
`driver_volume`, `conductor_volume`, `inside_volume`, `companion_volume`.
The response is that same object. Defaults are `1`.

The empty-command player object has to satisfy both parsers. `sub_140213E60`
reads `exist`, `player_id`, `player_name`, `tims`, and `title`.
`sub_140214460` also reads `web_point`, `total_web_point`, `meister_point`,
`latest_login_at`, optional `information` (`name`, `rank`, `mileage`,
`change_customize`, `registered_web`), optional `sound_config`, `tims`,
`title`, optional `realmode_item` (omitted), `badge_list`, `badge`,
`wappen_list`, `wappen`, and `mission_ticket`. `login` does not read
`tims` or `title`; extra fields are ignored. `login` still persists
`change_customize` and `latest_login_at`.

Title wire values: `type`, `rank`, and `train_line` are stored as json - 1,
so the server sends the stored byte plus one. `id`, `category`, and `year`
are as-is. TIMS items are `id`, `train_id`, `custom_id`, `name`,
`description`.

Seed on card `0123456789ABCDEF` / player `1`: shop lineup `1`, category
`wappen`, item id `1`, price `100`, status `0`, `buyable` true, name
`Local Wappen`. TIMS id `1`. `web_point` and `total_web_point` are at least
`1000` when the stored web point is below `100`. A purchase of lineup `1`
subtracts `100 * num` from `web_point`, upserts `owned_items`
(`wappen`, item `1`), and inserts `equipped_wappen` (size type `1`,
position `0,0`) when that row is missing. Later `playerbadge`,
`playerwappen`, and the empty-command player object return that wappen.

## Schema

File `server/data/content.sqlite`, created at runtime. Tables: `cards`,
`players`, `player_data`, `shop_lineup`, `owned_items`, `equipped_badges`,
`equipped_wappen`, `player_tims`, `leaderboards`, `credits`. A fresh database
inserts card `0123456789ABCDEF`, player id `1` (`Local Player`), five credits,
1000 web points, the lineup above, one TIMS row, and one leaderboard row on
`ranking`, `getmissionranking`, `getstoremileageranking`, and
`ranking_reward`. Older files gain the new columns with `ALTER TABLE` and
the same seed rows.

## DLL

`features::Content_Install` reads `moduleDir\config.ini`, calls `MH_Initialize`
(ignoring `MH_ERROR_ALREADY_INITIALIZED`), and enables only the hook on
`sub_140228CF0`. It does not open the database.
