# HUD hide — 2026-10-11

`features::Hud_Install` reads `[Hud] Enabled` from `config.ini` beside the
DLL. `Enabled=0` installs nothing, and `Hud_SetHidden` does nothing.
`Enabled=1` (the default in `config.ini`) hooks two game functions and
hides the driving HUD when free camera calls `Hud_SetHidden(true)`.

This is not the cheat MultiGate. That gate only broadcasts
`WholeGameManager.AllHudVisiblityDelegate` with `HudVisibleType`
`AllHiddun` (1), then `HUDsOnly` (2), then `AllVisibility` (0). `AllHiddun`
does not take the fade, the now-loading widgets, or the touch-panel root
down with the gauges. The hook does not wait for that key.

Image base `0x140000000`. Addresses below are preferred-base virtual
addresses. The hook adds the RVA to `GetModuleHandleW(nullptr)`.

## What the widgets do

`/Game/Blueprints/enumerator/HudVisibleType` is stored as
`NewEnumerator0..2`. In order those are `AllVisibility`, `AllHiddun`,
`HUDsOnly`.

`CenterScreenHUD`, `LeftScreenHUD`, `RightScreenHUD`, and `TouchPanelHUD`
bind `AllHudVisiblityDelegate_Event` on `WholeGameManager`. The center
handler compares that byte with 0, 1, and 2 and calls `SetVisibility` with
`ESlateVisibility` `Visible` (0) or `Hidden` (2). It also calls
`BackGroundBorder.SetVisibility`. `NowLoading.StartVisible` runs on the
show path. The same `SetVisibility` byte pair is in the touch handler.

The screen widgets keep the gauges and the overlays in different trees:

| Widget | Path | Overlays beside the gauges |
| --- | --- | --- |
| Center | `/Game/Blueprints/widget/inGame/BaseScreens/CenterScreenHUD` | `HUDsTree`, `Fade` / `FadeTree`, `NowLoading` (`NowLoading_Center_C`), `BackGroundBorder` |
| Left | `.../LeftScreenHUD` | `HUDsTree`, `Fade` / `FadeTree`, `loading_Left_C` |
| Right | `.../RightScreenHUD` | `HUDsTree`, `Fade` / `FadeTree`, `loading_Right_C` |
| Touch | `.../TouchPanelHUD` | `Fade` / `FadeTree`, `InGameNowLoadingBottom_C`, `tpHUD_root_C` (no `HUDsTree`) |

`WithFadeWidgetBase` creates `Fade_C` with `CreateFade` / `AddChildToCanvas`
and has its own `VisibilityLoadingCanvas_Delegate`. That path is not
`AllHudVisiblityDelegate`.

## What the hook hides

`UWidget::SetVisibility` is `sub_140D8B520` (RVA `0xD8B520`). `this` is
`rcx`, the visibility byte is `dl`. It stores `ESlateVisibility` at
`UWidget+0x91` and, when the Slate widget exists, pushes the converted
visibility through that widget's vtable. The byte values are the engine
enum: 0 Visible, 1 Collapsed, 2 Hidden, 3 HitTestInvisible,
4 SelfHitTestInvisible. The blueprints hide with 2, so the hook does too.

On `Hud_SetHidden(true)` the scan walks `GUObjectArray` (RVA `0x2F13580`,
chunk size 65536) and calls that function with Hidden on every live
instance of:

- `CenterScreenHUD_C`, `LeftScreenHUD_C`, `RightScreenHUD_C`, `TouchPanelHUD_C`
- `Fade_C`
- `NowLoading_Center_C`, `loading_Left_C`, `loading_Right_C`
- `InGameNowLoadingBottom_C`, `NowLoadingBottom_C`, `NowLoadingWord_C`
- `tpHUD_root_C`

For each of those it also walks `UUserWidget::WidgetTree` (`+0x190`,
`UWidgetTree::RootWidget` at `+0x28`) and `UPanelWidget::Slots` (`+0x118`,
slot content at `+0x30`). That covers `BackGroundBorder`, the fade image,
the loading widgets, and the touch controls that sit under those roots.
Class defaults, archetypes, and widgets owned by a blueprint generated
class are left alone.

`APlayerCameraManager::UpdateCamera` (RVA `0x14BD5B0`) runs the same pass
after the game's update, so a hide requested before the widgets exist is
applied when they spawn. The `SetVisibility` detour keeps a later game
write from showing a widget that was already saved.

## Restore

The first time a widget is hidden, its current `Visibility` byte is saved.
`Hud_SetHidden(true)` while that save exists does not overwrite it.
`Hud_SetHidden(false)` writes each saved byte back through the same
`SetVisibility` trampoline. A widget that was destroyed is skipped. Calls
made before `Hud_Install` finishes are ignored.

`FName::FName(const wchar_t*, EFindName)` is RVA `0x52EC80`.
`FName::ToString` is RVA `0x533220` and is used once to check that
`UserWidget` resolves before any widget is touched.
