# Card tap and player records — 2026-10-11

> Superseded on 2026-10-12: the poll and GetID hooks and the latched card were
> replaced by reader export stubs, and requests now reach the server through the
> NESYS service. On 2026-10-13 the stubs went too: the card is tapped on the
> keyboard device. See `2026-10-12-nesys.md`.

Target stays TG4AC 5.80.02, IDA instance `ida-35608`, image base `0x140000000`.
The game was not launched. `dll\ArrowheadUSBIO.dll` is not in the game folder,
so `sub_14020F2E0` never resolves the reader exports and byte `reader+25` stays 0.

## Key

`[Card]` in `config.ini` (next to `version.dll`, and the copy in this repo):

- `Enabled=1`
- `Key=P` (virtual key `0x50`)
- `Id=7070000000000001` (16 characters, prefix `707`)

P is in-game cheat binding 60. The tap is sampled with `GetAsyncKeyState` and
is not removed from the game's input. Free-camera keys are not touched.

## Hooks

Prologues are checked. A mismatch logs an error and that one target is left
unhooked. `MH_EnableHook` is called with that address only.

| Role | RVA | Prologue |
| --- | --- | --- |
| Poll `sub_140244E80` | `0x244E80` | `48 89 5C 24 08 57 48 83 EC 20` |
| GetID `sub_140223D80` | `0x223D80` | `40 53 57 41 54 41 57 48 83 EC 78` |
| `UMarshallingIO::Update` `sub_1402467A0` | `0x2467A0` | `48 89 5C 24 10 48 89 6C 24 18 56 57 41 56` |

Update is hooked so a P edge can set byte `this+132`. That is the only native
site that calls the poll. The poll then writes `this+124 = 1`. While that
frame is armed, `reader+26` is set and `NESiCAReaderGetResult` returns 1, so
the same Update broadcasts the delegate at `this+480`. GetID copies the 16-byte
`707` id and sets the status byte to 1. `NESYS_CARD_SELECT` (`sub_14023EA30`)
calls `sub_140002930`, which returns 0 unless that raw id is exactly 16 bytes
and returns -1 if the NESiS `Code` object is null.

Null reader exports are filled with stubs so a missing `ArrowheadUSBIO.dll`
still looks open. A real export pointer is left in place except `GetResult`
and `GetID`, which are swapped for the tap call and then restored.

## What was not proven live

The HTTP command name after `NESYS_CARD_SELECT` is still `sub_140005B50` →
`sub_1400070E0`. It is not an ASCII `selectcard` literal. The content DLL
already rewrites the AHAC host to `127.0.0.1:8750`. The local server accepts
`selectcard` for `7070000000000001` and returns `exist: true` plus player 1.
A new 16-character `707` or `709` code is registered on select.

## Server records

Card `7070000000000001` is seeded on player 1 (`Local Player`) together with the
existing credits, web points, wappen lineup, TIMS row, and leaderboard rows.
`0123456789ABCDEF` is kept. An existing database gains the `707` row with
`INSERT OR IGNORE` and does not move a card that is already stored.

`selectcard` of that id returns `exist: true` and the stored player. Login,
the empty path, and `selectcard` all read the same SQLite row, so the next
launch returns the name, title, TIMS, web points, meister points, badges,
wappen, equipped items, sound config, information/mileage, mission tickets,
and owned items.

Requests that carry those documented fields (`player_name`, `title`, `tims`,
`exp_mileage` / `mileage`, `meister_point`, `information`) update the row.
Credits, web points, shop purchases, equipped badges, equipped wappen, and
sound volumes already had their own writes.

| Command | Response the server returns |
| --- | --- |
| `playend` | `voice` and `priority` numbers (`sub_1402119B0`). The request (`exchangeable_dgp`, `play_companion`) is stored raw. |
| `gameresult` | `rank` grade strings (`SS`/`S`/`A`/`B`/`C`) and `clear_flag` (`sub_140214080`). Local grades are `A`, `clear_flag` is true. `exp_mileage` is written onto the player. |
| `gamemissionresult` | `rank` grades including `DelayRecoveryTime`, `clear` bools, `open_high`, `cl_mission` (`sub_1402122A0`). |
| `gametotalresult` | The fields read directly by `sub_140214D50`: `rank`, `clear_flag`, `high_score`, `realmode`, `change_title`, `driver_rank`, `exp_mileage`, `meister_point`, `meister_rank_up`. `exp_mileage` and `meister_point` are the stored player values. |

`gameover` and `result` still return the player object. `totalresult` does too.
Those names are not the recovered stubs.

### Still raw-only

the next call. No response schema was invented.

| Command | Why it stays raw |

| `getpicture`, `getpicturelist`, `postpicture` | Not decompiled. |
