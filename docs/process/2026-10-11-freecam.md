# Free camera — 2026-10-11

`features::Freecam_Install` reads `[FreeCamera]` from `config.ini` beside the
DLL and, when `Enabled` is non-zero, MinHooks the game's per-frame camera
update. While the free camera is on, the detour overwrites the view that
function just stored. This is the rendered `FMinimalViewInfo`, not an ImGui
camera and not `NativePhotographyCamera`.

Image base `0x140000000`. Addresses below are preferred-base virtual
addresses. The hook adds the RVA to `GetModuleHandleW(nullptr)`.

## Rejected leads

`GetPlayerCameraManager` at `0x1428F3700` (xref `0x1416BBBB5` in
`sub_1416BB6B0`) and `0x142971E40` (xref `0x141A2876D` in `sub_141A27030`)
are reflected function names, not the frame update.

`BlueprintUpdateCamera`, `GetCameraLocation`, and `GetCameraRotation` are
registered in `sub_1417E3200` (`Z_Construct` for `APlayerCameraManager`).
Those constructors publish names and property offsets. They do not run each
frame.

`UCameraComponentCustomizerBase` (FOV, HRZ, VCL, SCL, AGLX, AGLY, Yaw, HGT,
SDE) is the in-game adjust widget. `NativePhotographyCamera` is photo mode.
Neither is the active gameplay view.

A displacement of `+0x410` also shows up on unrelated objects. The offsets
below are tied to this class by its constructor and by the update function
that feeds `CameraCache`.

## Per-frame write

`APlayerCameraManager::UpdateCamera` is `sub_1414BD5B0`.

- Vtable slot `+0x5F0` (native `0x1423CFB48`, base `0x142848918`).
- Prologue: `rcx` = manager (`mov rbx, rcx`), `xmm1` = DeltaTime
  (`movaps xmm6, xmm1`).
- Gate matches the engine check: local player on `PCOwner`, or
  `bUseClientSideCameraUpdates` clear, or the debug bit. The local-player
  path calls virtual `+0x638` on the controller.
- Call into the writer at `0x1414BD600`:

```
movaps xmm1, xmm6          ; DeltaTime
mov    rcx, rbx            ; APlayerCameraManager*
call   qword ptr [rax+668h]
```

`APlayerCameraManager::DoUpdateCamera` is `sub_1414A4D80` (size `0x4E1`).

- Vtable slot `+0x668` (native `0x1423CFBC0`, base `0x142848990`).
- Prologue at `0x1414A4DB3` / `0x1414A4DCF`:

```
mov    rdi, rcx            ; this
movaps xmm10, xmm1         ; DeltaTime
lea    rdx, [rcx+0E90h]    ; ViewTarget.POV, copied onto the stack
```

- It blends `PendingViewTarget` (`target` at `0x13D0`, POV at `0x13E0`),
  runs view-target virtual `+0x680` and the modifier pass, then commits.
- Commit at `0x1414A51AE`:

```
ucomiss xmm0, dword ptr [rdi+400h]   ; world time vs CameraCache.TimeStamp
lea     rdx, [rdi+410h]              ; previous CameraCache.POV
lea     rcx, [rdi+950h]              ; LastFrameCameraCache.POV
mov     [rdi+940h], eax              ; LastFrame.TimeStamp
call    sub_141359140
mov     [rdi+400h], ecx              ; CameraCache.TimeStamp = world time
lea     rdx, [rsp+5C8h+var_598]      ; computed FMinimalViewInfo
lea     rcx, [rdi+410h]              ; CameraCache.POV
call    sub_141359140                ; 0x1414A51FA, the frame's view store
```

`sub_141359140` is the `FMinimalViewInfo` assignment. The first stores are
the view transform:

```
*(_QWORD *)a1       = *(_QWORD *)a2;        // Location.X, Location.Y
*(_DWORD *)(a1+8)   = *(_DWORD *)(a2+8);    // Location.Z
*(_QWORD *)(a1+12)  = *(_QWORD *)(a2+12);   // Rotation.Pitch, Rotation.Yaw
*(_DWORD *)(a1+20)  = *(_DWORD *)(a2+20);   // Rotation.Roll
*(_DWORD *)(a1+24)  = *(_DWORD *)(a2+24);   // FOV
```

The scene view is built later from this cache. Hooking
`DoUpdateCamera` and replacing the pose after the original returns puts the
free camera on that path. Post-process stays as the game wrote it. FOV is
seeded from the center POV and then driven with the bracket keys.

## Center camera

The shipping binary identifies itself as `++UE4+Release-4.15`. Stock
four-player splitscreen, in `UGameViewportClient`'s constructor, is:

| Call | Player | Origin | Cabinet frame |
| --- | --- | --- | --- |
| 0 | 0 | `(0, 0)` | left, top-left |
| 1 | 1 | `(0.5, 0)` | center, top-right |
| 2 | 2 | `(0, 0.5)` | right, bottom-left |
| 3 | 3 | `(0.5, 0.5)` | touch, bottom-right |

That is the frame this project already measures (`2026-10-11-display.md`,
`2026-10-11-layout.md`): source order left, center, right, touch. In 4.15,
`UWorld::Tick` walks the player-controller list from the front and each
local controller calls `UpdateCamera` → `DoUpdateCamera`. Controllers are
appended in local-player order, so the first manager in a frame is the left
cab and the second is the center cab.

The old hook consumed the F2 edge on that first call and then wrote that
pose into every later manager. The reported view keeps the scene position
and aims a little left, which is the left cab's pose on the center screen,
not a constant yaw error. No yaw offset is added. The activate log prints
the seeded pitch/yaw/roll beside the earlier call's, so the same-frame
difference stays visible.

A burst of calls closer than 5 ms is one frame. F2 waits for call 1 and
seeds that manager's `CameraCache.POV`. Call 0's manager is then overwritten
from the same pose, and calls 2 and 3 write it when they run. A frame that
only updates one manager (no center slot) seeds from that camera on the next
frame instead.

## Hook

`dll/src/features/freecam/freecam.cpp` hooks RVA `0x14A4D80` only.
`MH_Initialize` ignores `MH_ERROR_ALREADY_INITIALIZED`. `Enabled=0` installs
nothing.

After the original call, a rising edge of `Toggle` (default F2) seeds
location, rotation, and FOV from the center manager's `CameraCache.POV`,
clips the cursor to the output window, hides it, and recenters it. The first
mouse sample is dropped. While the free camera is on, one call per frame:

- mouse X adds yaw, mouse Y subtracts pitch (UE pitch is positive looking up).
  Pitch is clamped to [-89, 89] only after a non-zero mouse sample. The seeded
  pitch is the value the game wrote, so a cab camera looking down past 89
  degrees is left alone until the mouse actually moves
- WASD moves on the yaw heading: forward `(cos yaw, sin yaw, 0)`, right
  `(-sin yaw, cos yaw, 0)`. UE yaw 0 faces +X
- live speed starts at `10 * MoveSpeed` unreal units per second. The ini
  value 8 behaves as 80. Hold Q to multiply by about 0.5 each second, E by
  about 2. R snaps the live speed back to the 10x base and restores `g_seedFov`, the FOV seeded from the center `CameraCache.POV`. The live speed is clamped to
  [1, 100000]. Shift multiplies the step by `FastMultiplier`, Ctrl by
  `SlowMultiplier` (both apply if both are held). Ctrl does not move down
- Space / the Down key (default C) move on world Z
- `[` (`VK_OEM_4`) and `]` (`VK_OEM_5`) step FOV by 5 degrees, clamped to
  about [20, 150]. FOV is seeded from the center POV
- the same location, rotation, and FOV are written to `CameraCache.POV`,
  `LastFrameCameraCache.POV`, and `ViewTarget.POV` on every manager.
  `PendingViewTarget.POV` (`0x13E0`) is only blended inside `DoUpdateCamera`;
  `UpdateCamera` does not read it after the call, so it is not written

Input and movement run once per frame. The hook fires once per split screen;
applying the step on every manager would multiply speed by four, and 8
would not behave as 80.

Escape or another rising edge of the toggle key releases `ClipCursor`,
restores the `ShowCursor` count, and shows the HUD again
(`Hud_SetHidden`). The next `DoUpdateCamera` fills the cache from the train
camera again.

The cursor is clipped to the output window, not the cloaked game window.
`GetCursorPos` / `SetCursorPos` stay unremapped for that stretch: the touch
hook otherwise reports a point in the game's touch quadrant, and that
constant offset was applied as yaw every frame. Mouse movement is sampled
once per frame. A step larger than half the clipped output is discarded (2026-10-12). Yaw copied from
the game is wrapped into ±180. Pitch is not.

`Freecam_BlocksKeyMessage` eats the movement keys, Q, E, R, and the bracket
keys on the game window only while the free camera is on. Q and R are
in-game cheat keys. `[` and `]` are the cabinet LeftBracket and RightBracket.
They still reach the game while the free camera is off. See
`2026-10-11-game-keys.md` for the keys the game itself binds.
