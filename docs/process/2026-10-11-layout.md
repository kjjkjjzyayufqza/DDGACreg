# Layout presets — 2026-10-11

`features::Layout_Install` reads `[LayoutMode]` from `config.ini` beside the
DLL (`moduleDir` joined with `config.ini`) using `GetPrivateProfileStringW`.
A poll thread started there watches the cycle key and the arrow keys.
`Layout_Query(outputWidth, outputHeight)` is what the display compositor
calls each frame. No MinHook.

Source rects are fractions of the cabinet frame (3840x2160), in DDGUltrawide
order: left, center, right, touch. `LayoutRect` is `sizeX, sizeY, originX,
originY`.

| Panel | Focus | Source rect |
| --- | --- | --- |
| Left (frame top-left) | 0 | `{0.5, 0.5, 0, 0}` |
| Center (frame top-right) | 1 | `{0.5, 0.5, 0.5, 0}` |
| Right (frame bottom-left) | 2 | `{0.5, 0.5, 0, 0.5}` |
| Touch (frame bottom-right, top 822 rows) | 3 | `{0.5, 822/2160, 0.5, 0.5}` |

Forward panels are 1920x1080. The touch panel's used area is 1920x822.
Initial focus is the center panel. `Preset` defaults to `32:9` when the key
is missing or not one of `32:9`, `16:9`, or `single`.

## 32:9

`overridePlacements = false`, `activeCount = 4`. The display port keeps the
DDGUltrawide arcade cabinet, including its perspective. `source[]` is still
filled with the four cabinet rects above so a caller can read them. `dest[]`
is left unused.

## 16:9

`overridePlacements = true`, `activeCount = 4`. Flat panels on the output
window, with no cabinet perspective. The same source rects as 32:9 are kept.
Each picture is fitted inside its cell so a 16:9 monitor does not crop it.

The center cell is half the window width. Its row is as tall as a 16:9
picture in that cell (clamped to 35%–78% of the window). Each side cell is a
quarter of the width and the same row height; a 16:9 picture is letterboxed
inside it. The touch panel (1920:822) is fitted in the strip below.

On a 2560x1440 window the center is 1280x720, each side picture is 640x360,
and the touch picture is about 1682x720, all centered in their cells.

## single

`overridePlacements = true`, `activeCount = 1`. `source[0]` is the focused
panel's cabinet rect. `dest[0]` starts as the full window `{1, 1, 0, 0}` and
is then replaced by the aspect-fit of that panel inside the output:

- left, center, and right use 1920x1080
- touch uses 1920x822

The fitted rect is centered. A wider panel gets bars above and below; a
taller panel gets bars on the sides. A 16:9 panel on a 16:9 window stays
`{1, 1, 0, 0}`. Slots 1..3 are cleared.

## Keys

`CyclePreset` is a virtual-key name, default `F4`. Each press advances
`32:9` -> `16:9` -> `single` -> `32:9`. Names follow the rest of
`config.ini`: `F1`–`F24`, a letter or digit, or `SPACE`, `UP`, `DOWN`,
`LEFT`, `RIGHT`, and the other names listed in the reader.

Arrow keys select the focused panel. The mapping follows the cabinet frame,
not screen-relative "up means the top row":

| Key | Focus | Panel |
| --- | --- | --- |
| Left | 0 `LayoutFocus_Left` | game frame top-left |
| Up | 1 `LayoutFocus_Center` | game frame top-right |
| Right | 2 `LayoutFocus_Right` | game frame bottom-left |
| Down | 3 `LayoutFocus_Touch` | game frame bottom-right |

Presses are edge-triggered. Arrows are ignored while Ctrl or Alt is down, so
DDGUltrawide `Ctrl+Alt+arrows` can still change cabinet perspective. Focus
is tracked in every preset and is applied when the preset is `single`.
